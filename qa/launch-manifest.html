How to run this

Assign whole sections to testers — each is scoped to ~15–30 min and lists the accounts you'll need. Log into a real (non-prod-critical) account per role and work top to bottom. File anything that fails wherever your team tracks bugs; this page only tracks what's been checked, not the bug detail.

Priority key

P0 — core path; a failure here should hold the launch
P1 — important; fix soon, doesn't have to block
P2 — secondary path, verify if time allows

Known limitation tag

EXPECTED next to a check means the PRD documents that behavior as a deliberate v1 gap (e.g. no single-occurrence edits on recurring events). Confirm it behaves as described — it isn't a bug to report.

Automation tag

Each check is also tagged for whether it's worth scripting once a test harness exists (there isn't one yet — see below). AUTO deterministic app/DB logic, no live third party. SETUP needs real Clerk/Stripe/Google/email plumbing first. MANUAL genuinely needs a human (visual feel, long-horizon email tone).
